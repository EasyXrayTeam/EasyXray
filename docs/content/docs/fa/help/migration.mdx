## از X-UI / 3x-ui

**EasyXray یک نصب موجود X-UI یا 3x-ui را مهاجرت نمی‌دهد.** هیچ مرحلهٔ تشخیص، هیچ دستور
import و هیچ تبدیل خودکاری وجود ندارد. این دو محصول دقیقاً در همان جاهایی که یک مهاجرت
باید به آن‌ها نگاه کند، آگاهانه متفاوت‌اند:

| | X-UI / 3x-ui | EasyXray |
| --- | --- | --- |
| سرویس و دستور | `x-ui` | `easyxray` |
| پیکربندی / پایگاه‌داده | مسیرهای خودش | `/etc/easyxray/EasyXray.db` |
| پیشوند متغیرهای محیطی | `XUI_*` | `EASYXRAY_*` |
| فضای نام HTTP | `/panel/…` | `/easyxray/…` |

نصب EasyXray روی سروری که از قبل X-UI/3x-ui اجرا می‌کند، یک **نصب تازه و موازی** است —
نسخهٔ قبلی را جایگزین یا ارتقا نمی‌دهد. برای انتقال، EasyXray را از نو نصب کنید،
inboundها و کلاینت‌هایتان را دوباره بسازید و لینک اشتراک‌گذاری هر کلاینت را از پنل قدیمی
خروجی بگیرید تا در سمت کلاینت وارد کنید. استفادهٔ مجدد از فایل SQLite قدیمی پشتیبانی
نمی‌شود، چون schema آن‌ها متفاوت است.

همین موضوع دربارهٔ خودکارسازی هم صادق است: REST API از `/panel/api/…` به
`/easyxray/api/v1/…` منتقل شده و پیشوند قدیمی **هیچ نام مستعار سازگاری‌ای ندارد**.
اسکریپت‌ها، ربات‌ها و داشبوردهایی که برای `/panel/api/…` نوشته شده‌اند باید به‌روزرسانی شوند.

## بین سرورها

انتقال همان نصب EasyXray به سرور جدید در واقع یک جابه‌جایی پایگاه‌داده است:

<Steps>

<Step>
### از سرور قدیمی نسخه پشتیبان بگیرید

از پایگاه‌داده (به‌صورت پیش‌فرض `/etc/easyxray/EasyXray.db`) و گواهی‌نامه‌های خود یک کپی تهیه کنید.
[پشتیبان‌گیری و بازیابی](/docs/operations/backup-restore) را ببینید.
</Step>

<Step>
### EasyXray را روی سرور جدید نصب کنید

از همان روش نصب و یک نسخهٔ سازگار استفاده کنید.
[نصب](/docs/guide/installation) را ببینید.
</Step>

<Step>
### پایگاه‌داده را بازیابی کنید

پنل را متوقف کنید، پایگاه‌داده را در جای خود قرار دهید، گواهی‌نامه‌ها را بازیابی کرده و پنل را راه‌اندازی کنید. هر تنظیم وابسته به IP یا دامنه را بازبینی کنید.
</Step>

</Steps>

## بین نسخه‌های EasyXray

در محدودهٔ یک backend یکسان، ارتقا معمولاً تنها به اجرای دوبارهٔ نصب‌کننده یا
کشیدن یک image جدید خلاصه می‌شود — پنل خودش پایگاه‌داده‌اش را مهاجرت می‌دهد. هنگام تغییر بین نسخه‌های **اصلی**،
ابتدا [یادداشت‌های انتشار](https://github.com/EasyXrayTeam/EasyXray/releases)
را بخوانید و یک نسخهٔ پشتیبان تهیه کنید.

<Callout type="warn">
  پیش از هر مهاجرتی همیشه یک نسخهٔ پشتیبان تهیه کنید و سرور قدیمی را تا زمانی که
  از درستی عملکرد سرور جدید مطمئن نشده‌اید، روشن نگه دارید.
</Callout>
