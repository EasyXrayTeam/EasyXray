پنل EasyXray یک REST API برای خودکارسازی در اختیار می‌گذارد. صفحات این بخش از
مشخصات OpenAPI خود پنل تولید شده‌اند، بنابراین همواره با اسکیمایی که پنل واقعاً
ارائه می‌دهد هماهنگ هستند.

## فضای نام

هر آنچه پنل ارائه می‌دهد زیر **مسیر پایهٔ پیکربندی‌شدهٔ وب** (`webBasePath`) و سپس
`easyxray` قرار دارد:

| سطح               | مسیر                                      |
| ----------------- | ----------------------------------------- |
| رابط پنل          | `<basePath>/easyxray/…`                   |
| REST API          | `<basePath>/easyxray/api/v1/…`            |
| WebSocket         | `<basePath>/easyxray/ws`                  |
| مشخصات OpenAPI    | `<basePath>/easyxray/api/v1/openapi.json` |

با مسیر پایهٔ پیش‌فرض (`/`)، برای مثال یعنی:

```text
GET  /easyxray/api/v1/inbounds/list
POST /easyxray/api/v1/clients/add
GET  /easyxray/api/v1/server/status
GET  /easyxray/api/v1/openapi.json
```

<Callout type="warn">
  **فضای نام `easyxray` نام مستعار ندارد.** نسخه‌های پیشین پنل X-UI/3x-ui این
  endpointها را زیر `/panel/api/…` ارائه می‌کردند؛ EasyXray روی آن پیشوند
  **پاسخی نمی‌دهد** و هیچ ریدایرکت سازگاری نصب نشده است. هر اسکریپت، ربات یا
  داشبوردی که برای مسیرهای قدیمی نوشته‌اید باید به مسیرهای `/easyxray/api/v1/…`
  در بالا به‌روزرسانی شود.
</Callout>

## احراز هویت

درخواست‌ها یا با یک **کوکی نشست** — که هنگام ورود به پنل تنظیم می‌شود و نامش
`easyxray` است — یا با یک **توکن Bearer** احراز هویت می‌شوند:

```text
Authorization: Bearer <token>
```

توکن‌های API را در **تنظیمات → امنیت → توکن API** بسازید؛ این توکن‌ها
اعتبارنامه‌های ادمین کامل هستند، پس آن‌ها را مانند رمز عبور پنل نگهداری کنید. به
[توکن‌های API](/docs/reference/api/api-tokens) مراجعه کنید.
